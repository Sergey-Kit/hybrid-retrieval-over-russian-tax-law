# Сетевые условия сбора

## Замер 2026-08-20

Весь трафик машины шёл через личный VLESS/Reality-VPS, выход — **Хельсинки, AEZA, AS210644**.

| Хост | :443 | :80 |
|---|---|---|
| `pravo.gov.ru` | SYN дропается | открыт |
| `publication.pravo.gov.ru` | SYN дропается | открыт |
| `www.nalog.gov.ru` | открыт | открыт |

`pravo.gov.ru` фильтрует 443 для иностранных адресов. Это, а не защита от роботов, стоит
за формулировкой спеки «сайт не отдаётся автоматическим запросам»: по 80 он отвечает.

## Почему сбор через VPN запрещён в коде

Он работает — и в этом проблема. Источник фильтрует адрес, отдаёт по незашифрованному
каналу неизвестно насколько полное содержимое, а тротлинг иностранного IP на длинном
краулинге не проявится ни в кодах ответа, ни в логах. Получится правдоподобно-неполный
корпус, и узнать об этом можно будет только от пользователя продукта.

Поэтому `p3.netcheck.preflight` **останавливает сбор**, если

* порт 443 у источника недоступен, либо
* внешний IP не в стране `P3_EXPECTED_EXIT_COUNTRY` (по умолчанию `RU`).

Недоступность геосервиса сама по себе сбор не блокирует.

## Что нужно сделать

Пустить домены источников напрямую, мимо туннеля (split-tunnel):

```
pravo.gov.ru
publication.pravo.gov.ru
www.nalog.gov.ru
```

и проверить:

```bash
PYTHONPATH=src python -m p3.cli collect-fns -v
```

`P3_SKIP_PREFLIGHT=1` существует для оффлайн-прогонов из кэша и для тестов. Для сбора
данных его использовать нельзя.

## Следствие для аренды сервера

Арендованная машина — это иностранный IP, то есть для `pravo.gov.ru` она **хуже** домашнего
подключения. Собственный VPS проекта стоит в Финляндии и упрётся в ту же фильтрацию.
Скрейпинг на 1 rps идёт с локальной машины; аренда в P3 уместна только под разовый прогон
эмбеддеров на вехе 2.
