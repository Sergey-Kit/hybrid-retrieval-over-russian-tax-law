# Сетевые условия сбора

## Что оказалось правдой

| Хост | :443 | :80 | HTTPS отдаёт? |
|---|---|---|---|
| `pravo.gov.ru` | закрыт | открыт | **нет, ни для кого** |
| `publication.pravo.gov.ru` | закрыт | открыт | **нет** |
| `www.nalog.gov.ru` | открыт | открыт | да |

Проверено с двух разных выходов — через VPN (Финляндия) и с прямого подключения из РФ.
Результат одинаковый.

## Ошибка, которая тут стояла

Сначала закрытый 443 был истолкован как **геофильтрация иностранных адресов**, и на этом
была построена жёсткая блокировка: сбор запрещался, пока трафик идёт через VPN. Логика
казалась убедительной — «источник фильтрует наш адрес, значит отдаёт неизвестно что».

Проверка с российского адреса это опровергла: 443 закрыт и оттуда. Сайт просто работает
по HTTP. Блокировка запрещала бы сбор навсегда, при этом ссылаясь на несуществующую причину.

Вывод, который стоит запомнить: **закрытый порт — это наблюдение, а «нас фильтруют» — уже
интерпретация.** Разница между ними стоила бы недели простоя, если бы её не поймали.

## Что проверяется сейчас

`p3.netcheck.preflight` останавливает сбор, только если порт 443 недоступен у источника,
который HTTPS **действительно отдаёт** (`Source.require_tls`).

Страна выхода **не блокирует** сбор:

* гео-сервисы расходятся в показаниях для одного и того же выхода (получены FI и GB);
* из России без VPN они недоступны — то есть ровно тогда, когда нужны.

Вместо запрета — прослеживаемость: страна выхода пишется в `data/raw/manifest.jsonl`
рядом с каждым документом. Если полнота корпуса окажется под вопросом, будет видно,
откуда он собран.

## Проверка

```bash
PYTHONPATH=src python3 -m p3.cli netcheck
```
