# P3 — гибридный retrieval по налоговой нормативке РФ

Поиск по Налоговому кодексу с темпоральной корректностью: не «что написано в НК», а
**«что было написано в НК на такую-то дату»**. Генерации здесь нет и не будет — граница
проекта проходит по возврату правильных фрагментов нормы.

Техническое задание — [`P3_retrieval_SPEC.md`](P3_retrieval_SPEC.md). Этот файл описывает
**фактическое состояние**, включая места, где реальность разошлась с ТЗ.

## Главный результат вехи 1

ТЗ §5 называет один вопрос «самым высоколевереджным неизвестным во всём проекте»:
доступны ли в ИПС «Законодательство России» датированные редакции статей НК. От ответа
зависело, недели работы или месяцы — потому что альтернатива это **собственный
консолидатор**, восстанавливающий текст кодекса на дату из первой редакции плюс сотен
законов-поправок, с парсером формулировок вида «в пункте 3 слова X заменить словами Y».

**Ответ: редакции доступны.** [`docs/spike-ips.md`](docs/spike-ips.md)

| | |
|---|---|
| НК ч.1 в ИПС | `nd=102054722`, **153 редакции**, `rdk` 0…248 |
| Охват по годам | **1999–2026** |
| Редакций за период с 2021 | **79** — ровно окно, которое требует ТЗ |
| Тексты редакций | доступны; на выборке 14 редакций 2021–2026 — **14 из 14** |
| НК ч.2 | `nd=102067058` |

Следствие: **консолидатор уходит с критического пути** и становится верификатором.
`consolidator_accuracy` из ТЗ §5 теперь считается *против* редакций ИПС, а не *вместо* них.

Попутно снята ложная предпосылка ТЗ «сайт не отдаётся автоматическим запросам». Отдаётся.
`pravo.gov.ru` дропает SYN на 443 для иностранных адресов, но отвечает по 80 — это
геофильтр, а не защита от роботов. А первый поисковый запрос вернул «не найдено» просто
потому, что уходил в поле «Вид акта» вместо «Наименование».

## Второй результат: разметка нашлась готовой

ТЗ §2 предлагает строить silver set, вытаскивая цитаты норм из текстов писем регулятором.
Разведка дала способ лучше: сервис ФНС «Решения по жалобам» **размечает решения сам**.
Каждая запись несёт и описание спора живым текстом, и статьи НК, к которым ФНС это
решение отнесла. [`docs/silver-set.md`](docs/silver-set.md)

Из-за этого целый класс ошибок, который ТЗ §10 перечисляет отдельной строкой — «нормы не
приведены к `norm_unit_id`, совпадения не засчитываются, метрики занижены», — **для этого
источника не возникает по построению**: эталон не извлекается эвристикой, а берётся из
поля, заполненного ведомством.

Побочно это дало независимую проверку нормализатора ссылок на 263 ярлыках, написанных ФНС:

| | |
|---|---|
| Ярлыков статей НК разобрано верно | **251 из 251** |
| Не-НК корректно отброшено (КоАП, ГК, 129-ФЗ, постановления) | **12 из 12** |
| Известный пробел | «Глава 26.2 НК РФ» — глав нормализатор не знает |

## Три расхождения с ТЗ, принятые сознательно

**1. Silver set делится на train/dev/test.** ТЗ §7 предлагает подбирать на нём веса BM25F
и параметр RRF, а §9 принимает на нём же `Recall@20 ≥ 0.9`. Это замер на обучающей
выборке. Здесь: тюнинг только на train и dev, отчётные числа — один раз на test, а
отсутствие утечки между сплитами проверяется тестом.

**2. Эмбеддер — `deepvk/USER-bge-m3`, сравнение из трёх.** ТЗ §4 ставит выбор как «FRIDA
против BGE-M3» и не рассматривает третий вариант:

| Модель | Параметры | dim | Контекст |
|---|---|---|---|
| `ai-forever/FRIDA` | 823M | 1536 | **512** |
| `BAAI/bge-m3` | ~568M | 1024 | 8192 |
| **`deepvk/USER-bge-m3`** | **359M** | 1024 | **8192** |

Контекст 8192 означает, что ловушка обрезки из ТЗ §4 не возникает по построению, а
чанкинг остаётся энкодеро-независимым — то есть сравнение моделей идёт на одних и тех же
чанках. У FRIDA к тому же `dim=1536`, а не 1024: в полтора раза больше памяти под векторы
и в полтора раза более медленный перебор на CPU без AVX2.

**3. BM25F — своей реализацией, не в Postgres.** Довод ТЗ §3.4 «BM25 в той же СУБД, без
синхронизации двух хранилищ» на практике не выполняется: `ts_rank` не является BM25 и не
умеет полевые веса `body`/`title`, которые ТЗ требует тюнить. Рассинхрон гасится не «одной
СУБД», а общим `corpus_build_id` и ассертом на совпадение множеств чанков.

## Тихие дефекты, найденные фактически

ТЗ §10 перечисляет ожидаемые. Эти обнаружены на реальных данных, и все отдают HTTP 200.

| Дефект | Что было бы |
|---|---|
| `rdk` обходится как диапазон, а не как список | 96 из 249 значений не существуют и отдают заглушку «Текст документа отсутствует» — 96 фиктивных редакций в корпусе |
| `value` опции разбирается как число | это `rdk,nd`; парсер работает по совпадению и падает на другом формате |
| `<option>` ищется в сыром HTML | разметка внутри `<script>` попадает в перечень редакций |
| Сбор идёт через VPN с иностранного IP | источник фильтрует адрес, отдаёт неизвестно насколько полное содержимое, тротлинг не виден в логах |
| Ссылка без названия кодекса уходит в НК по умолчанию | «статьей 5 Федерального закона» становится нормой НК |

Каждый закрыт тестом или ассертом, а не комментарием.

## Устройство

```
src/p3/
  config.py        устройство, троттлинг, источники — из окружения, не из кода
  netcheck.py      преflight: падает, если 443 закрыт или выход иностранный
  raw_store.py     контентно-адресуемое сырьё + манифест в git
  fetch.py         1 rps, robots.txt, ретраи, кэш
  refs/normalize.py   «подпунктом 2 пункта 1 статьи 31» -> nk1:31:p1:sp2
  sources/ips.py      ИПС: поиск, карточка, редакции, тексты
  sources/nalog_ru.py решения по жалобам ФНС
  silver/             разметка, дедуп, сплит
  cli.py              spike-ips | collect-fns | build-silver
```

Всё скачанное сохраняется байт-в-байт **до** парсинга и хешируется; манифест лежит в git,
байты — нет. Повторный прогон читает из кэша и в сеть не ходит.

## Ограничения, которые надо знать

* **Silver set попадает не в ту предметную область.** Пар 1678, но статьи слоя 1 —
  процедуру, ради которой строится продукт, — задевают только **52 из них (3%)**, в тестовом
  сплите **8 из 337**, а по ст. 6.1 «исчисление сроков» запросов **ноль**. Источники
  покрывают всё налоговое право, продукт же обслуживает узкий процедурный срез. Поэтому
  recall по этому набору **нельзя публиковать как продуктовую метрику** —
  см. [`docs/silver-set.md`](docs/silver-set.md) §4а.
* **`pravo.gov.ru` работает только по HTTP** — не по геофильтру, а вообще; сайт не отдаёт
  HTTPS никому. Страна выхода при сборе пишется в манифест как происхождение.
* **Silver set смещён**: решения по жалобам — это споры, а не типичные вопросы; негативов
  нет; `as_of` нет; «тема спора» написана ведомством, а не налогоплательщиком.
* **Эталон на уровне статьи**, не пункта: ФНС размечает статьями.
* **Условия использования ИПС не подтверждены** — блокирующий вопрос для коммерческого P5.
* **Дата редакции ≠ дата вступления в силу.** Отображение одного в другое — задача вехи 2,
  и ошибка здесь будет тихой: фильтр заработает, но по неверной дате.
* Замеры латентности на этой машине (GTX 1650 SUPER, 8 ГБ RAM, CPU без AVX2) — **сравнение
  конфигураций между собой**, а не абсолютные числа продукта.
